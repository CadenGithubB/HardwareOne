# Known issues

Open problems that affect users, with the workaround where one exists. Entries leave when the fix
is on `main` and has a dated hardware check. Readiness item P1-12; the release gate in `RELEASING.md`
requires every open P1 defect to be listed here or fixed.

| Area | Problem | Workaround | Status |
|---|---|---|---|
| ESP32-P4 (P4X-EYE, Waveshare) | Occasional reboot (`reset=panic`, heap-corruption abort or a load fault in the VFS table) a few seconds after a speech session ends or when one starts with the radio on. Root cause found on 2026-11-07: the CPU clock is switched (400 MHz during a session, lower afterwards) without the MSPI/PSRAM speed-mode sync, so PSRAM transfers land at the wrong address. | Keep the CPU at a constant clock (Performance power mode) until the fix lands. | Fixed on this line (clock switch with the MSPI sync and memory quiesce, `System_Power.cpp`), verified on the bench P4X-EYE for 300 clock toggles and 40 fast sessions; long 10-minute sessions on the fixed build not yet re-measured. See `docs/P4X_PANIC_HUNT_20261107.md`. |
| ESP32-P4 | `task_wdt: IDLE0` register dumps ~8 s after boot and right after a Wi-Fi join: the main loop holds core 0 for 7-9 s (LOOPHEALTH IO stall). Cosmetic, the watchdog does not panic. | None needed. | Open; a ticket, not a release blocker. |
| Local STT (P4) | A speech session occasionally fails to start with `warm-up failed: Cancelled` (4 of 40 fast start/stop cycles on 2026-11-07). | Start it again. | Open. |
| Local STT (P4) | Quiet speech more than about a foot from the microphone is not captioned: the onset rule needs speech ~10 dB above the room. | Speak closer, or try `sttdecisionpre 97`, `pdmhpf 120`, `pdmamplify 8` (all default off; bench-verified offline, one device arm). | Open; see `docs/STT_MIC_PATH_INVESTIGATION_20261107.md`. |
| Debug logging | Two persistent owners of the debug mask: the system-log autostart re-applies the saved `log start flags=` mask on every boot, so a mask turned off at runtime returns after a reboot. | Clear the saved flags with `log` before rebooting. | Open (readiness Section 8). |
| Host test suite | The four browser suites (`map_live_browser`, `g2_status_browser`, `sensor_mic_card`, `logging_system_config_browser`) are disabled without Node.js; `ctest` reports them as not run. | Install Node.js (`HW1_NODE_EXECUTABLE` for a custom path) before the release gate. | By design; documented in `RELEASING.md`. |
| OTA | The recovery OTA layouts have no dated PASS on a current image (last FeatherS3 record 2026-08-05 at v0.99.8; Feather V2 2026-08-25). | Cable update until the release bench run records PASS lines. | Scheduled for the release candidate bench (readiness P0-6). |
| Account recovery | A single-account device cannot recover a lost admin password in place: `factoryreset` needs a super-admin login. | Keep a second admin, or erase the LittleFS region over the cable (settings and captures are lost). | Documented in `docs/COMPATIBILITY.md`; first-time setup now refuses names that would lock the device out. |
| Waveshare ESP32-P4 Touch LCD 5 | Experimental board: bring-up acceptance records exist, but no soak or OTA qualification. | Use as a development board. | Experimental in the support matrix. |
| Seeed XIAO ESP32S3 (base, no Sense) | Not selectable: every ESP32-S3 build defines `XIAO_ESP32S3_SENSE_ENABLED` (`CMakeLists.txt`, after `project()`), so a base XIAO gets the Sense build, whose camera, microphone and SD card expect the Sense expansion board. | Use the XIAO ESP32S3 Sense. | Open (readiness G-63). |
| WiFi | Auto-reconnect retries only the network that dropped. The hunt across all saved networks runs only at boot, on `openwifi` and when the radio is switched back on, so a device moved to another saved network stays offline. | Run `openwifi`, or add an interval automation such as `automation add name=wifihunt type=interval intervalms=300000 commands="IF WIFI=NONE THEN openwifi" enabled=1` (it also reopens WiFi after `closewifi`; disable it while you want WiFi off). | Open (readiness G-66). |
| Recording | The WAV header is written with a zero length at start and completed only when the recording stops, and nothing is flushed meanwhile, so a recording cut by a power loss or reset is lost (recordings are capped at 60 s). | None; stop the recording before removing power. | Open (readiness G-69). |
| Automations | Every fire of an interval trigger rewrites `/system/automations.json` to save its next run time, so intervals of a few seconds wear the flash over months. | Use intervals of 60 s or longer, or an event trigger. | Open (readiness G-70). |
| Web UI | The web server has one worker task, so handlers run one at a time: an upload or a slow client can hold the UI for up to 20 s (HTTPS) or 30 s (HTTP) socket timeouts, and each events (SSE) poll holds the worker for about 0.6 s. | Avoid other web actions during uploads; close idle tabs. | Open (readiness G-72). |
| Power (FeatherS3) | In Performance, Balanced or UltraSaver mode the idle downclock changes the CPU clock, which once collided with in-flight sensor reads such as GPS (fixed in v0.98.8: the switch now drains the I2C buses first). The ESP32-S3 switch path changed again on 2026-11-08 (MSPI speed-mode sync) and is host-tested only; a 30-minute bench soak with GPS running is pending. | Adaptive (the default) or Locked, which do not change the clock at idle. | Open (readiness G-74, G-48). |
| ESP-NOW security | Session keys, the rekey private key, the bond token and the decrypt buffer live in PSRAM, so with flash encryption off they can be read with bench (physical) access to the device. | Enable flash encryption (for example `feathers3_fe`); re-bond the other devices after one is lost. | Open (readiness G-77). |
| Time | Plain SNTP replies are trusted as they arrive (lwIP steps the clock before the firmware sees them), so an attacker on the same LAN can set the device clock, moving timed automations and timestamps. | Use a trusted network. | Open (readiness G-79). |
| Device handover | `factoryreset` removes the accounts, their settings and transcripts, and the phone-pipe code; saved WiFi networks, MQTT and LLM endpoint credentials, other Bluetooth bonds and the ESP-NOW identity and keys stay. | Before giving a device away, erase the whole flash over the cable (`tools/build_board.sh <board> -p PORT erase-flash`) and flash it again; see the User Guide, Account recovery. | Open (readiness G-80). |
