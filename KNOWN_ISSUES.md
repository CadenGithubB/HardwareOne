# Known issues

Open problems that affect users, with the workaround where one exists. Entries leave when the fix
is on `main` and has a dated hardware check.

| Area | Problem | Workaround | Status |
|---|---|---|---|
| ESP32-P4 (P4X-EYE, Waveshare) | Occasional reboot (`reset=panic`, heap-corruption abort or a load fault in the VFS table) a few seconds after a speech session ends or when one starts with the radio on. Root cause found on 2026-11-07: the CPU clock is switched (400 MHz during a session, lower afterwards) without the MSPI/PSRAM speed-mode sync, so PSRAM transfers land at the wrong address. | Keep the CPU at a constant clock (Performance power mode) until the fix lands. | Fixed on this line (clock switch with the MSPI sync and memory quiesce, `System_Power.cpp`), verified on the bench P4X-EYE for 300 clock toggles and 40 fast sessions, and on 2026-11-08 for eleven 7.5-10.5 minute continuous sessions plus 60 fast start/stop cycles (no panic, no dropped audio). See `docs/P4X_PANIC_HUNT_20261107.md` and `docs/STT_MIC_PATH_INVESTIGATION_20261107.md` section 6. |
| ESP32-P4 | `task_wdt: IDLE0` register dumps ~8 s after boot and right after a Wi-Fi join: the main loop holds core 0 for 7-9 s (LOOPHEALTH IO stall). Cosmetic, the watchdog does not panic. The opt-in watchdog soak build (`--wdt-soak`) uses a 20 s timeout to clear it. | None needed. | Open; a ticket, not a release blocker. |
| Local STT (P4) | A speech session occasionally fails half a second after starting with `Microphone audio loss detected` (logged as `warm-up failed: Cancelled`): 4 of 40 fast start/stop cycles on 2026-11-07, 1 of 20 on 2026-11-08, all with the bench raw recorder (`sttraw`) armed. The onboard mic's 256 ms DMA ring overflowed before the session's first read, while the recorder opened its SD file, and the strict loss rule counted that pre-session audio. | Start it again. | Fixed on this line: the loss baseline is taken just before the first read (`TL capture_preroll_overrun` logs a pre-read drop); 40 of 40 fast cycles with `sttraw` armed on 2026-11-08. |
| Local STT (P4) | Quiet speech more than about a foot from the microphone was not captioned: the loudness onset rule needed speech ~10 dB above the room. | None needed on this line. | Fixed on this line by the automatic defaults (`sttdecisionpre 97`, `sttautogain 1`: STT's own gain, agreed over sessions, and a 120 Hz high-pass): at 1 ft quiet read speech is captioned 8/8 instead of 0/8, all-WER 72 -> 44-48%, no false captions; see `docs/STT_MIC_PATH_INVESTIGATION_20261107.md` sections 6-7. Background talkers are captioned more often. The G2 glasses mic has its own profile (`sttg2*`, judge on by default after the same bench check, section 8). |
| R1 ring health history | A forged SNTP reply (plain SNTP is trusted as it arrives) moves the device clock, and the device then pushes that clock to a connected ring, which keys its daily pages off that clock. A clock jump alone no longer deletes stored days, but each day stored with a far-future date pushes the oldest of the 30 kept days out, so a ring left on a forged clock for a month loses its stored history. | Use a trusted network. | Open. |
| Debug logging | Two persistent owners of the debug mask: the system-log autostart re-applies the saved `log start flags=` mask on every boot, so a mask turned off at runtime returns after a reboot. | Clear the saved flags with `log` before rebooting. | Open. |
| Host test suite | The four browser suites (`map_live_browser`, `g2_status_browser`, `sensor_mic_card`, `logging_system_config_browser`) are disabled without Node.js; `ctest` reports them as not run. | Install Node.js (`HW1_NODE_EXECUTABLE` for a custom path) before the release gate. | By design; documented in `RELEASING.md`. |
| OTA | The recovery OTA layouts have no dated PASS on a current image (last FeatherS3 record 2026-08-05 at v0.99.8; Feather V2 2026-08-25). | Cable update until the release bench run records PASS lines. | Scheduled for the next release bench run. |
| OTA | On the recovery OTA layout `idf.py erase-flash` (and `erase_flash`) is not refused, unlike the stock `flash` and erase targets: idf.py runs esptool directly, so the whole chip is erased, including the `factory` recovery updater, NVS (the recovery credential) and `littlefs`. | To wipe only the filesystem use `littlefs-flash` (`encrypted-littlefs-flash` on `feathers3_fe`); to replace only the updater use `factory-flash` (`encrypted-factory-flash`). After a full erase, provision again with `migration-flash` (`encrypted-migration-flash` on `feathers3_fe`), then `setpin` or `otapin`: `docs/OTA_DEVICE_SETUP.md`, "Known rough edges". | Open; documented. |
| Account recovery | A single-account device cannot recover a lost admin password in place: `factoryreset` needs a super-admin login. | Keep a second admin, or erase the LittleFS region over the cable (settings and captures are lost). | Documented in `docs/COMPATIBILITY.md`; first-time setup now refuses names that would lock the device out. |
| Backup restore | "Import from Backup" is not one transaction. Every file is staged and checked first, then moved into place one rename at a time, so a power cut during that last step can leave a mix of old and new files. `users.json` goes last, so until it lands the device still boots into first-time setup. | Run Import from Backup again with the same bundle after the reboot. | By design (per-file promotion). |
| Waveshare ESP32-P4 Touch LCD 5 | Experimental board: bring-up acceptance records exist, but no soak or OTA qualification. | Use as a development board. | Experimental in the support matrix. |
| Seeed XIAO ESP32S3 (base, no Sense) | Not selectable: every ESP32-S3 build defines `XIAO_ESP32S3_SENSE_ENABLED` (`CMakeLists.txt`, after `project()`), so a base XIAO gets the Sense build, whose camera, microphone and SD card expect the Sense expansion board. | Use the XIAO ESP32S3 Sense. | Open. |
| WiFi | Auto-reconnect retries only the network that dropped. The hunt across all saved networks runs only at boot, on `openwifi` and when the radio is switched back on, so a device moved to another saved network stays offline. | Run `openwifi`, or add an interval automation such as `automation add name=wifihunt type=interval intervalms=300000 commands="IF WIFI=NONE THEN openwifi" enabled=1` (it also reopens WiFi after `closewifi`; disable it while you want WiFi off). | Open. |
| WiFi | `openwifi` connects synchronously on the shared command executor, so while it runs every other command, from every transport, waits behind it. With saved networks that associate but fail (wrong password, weak link), plain `openwifi` (the best-network hunt, also run by the web Wi-Fi "save and connect" button) holds it for up to about 150 s (the hunt budget; each network gets up to three 35 s attempts). `openwifi --index` and `--saved-id` give the chosen network the same three 35 s attempts (about 110 s) and then up to about 50 s to rejoin the previous network, so up to about 160 s. A network that is out of range gives up after a few seconds per attempt. A web caller gets a timeout after 60 s while the attempt continues. | Wait for it to finish; the console shows each `Connecting to` / `Retrying` line. An `openwifi` typed on the serial console stops at the next key press. Use `--index <n>` for a network you know is in range, so only that one is tried. | Deferred. |
| Recording | The WAV header is written with a zero length at start and completed only when the recording stops, and nothing is flushed meanwhile, so a recording cut by a power loss or reset is lost (recordings are capped at 60 s). | None; stop the recording before removing power. | Open. |
| Automations | Every fire of an interval trigger rewrites `/system/automations.json` to save its next run time, so intervals of a few seconds wear the flash over months. | Use intervals of 60 s or longer, or an event trigger. | Open. |
| Web UI | The web server has one worker task, so handlers run one at a time: an upload or a slow client can hold the UI for up to 20 s (HTTPS) or 30 s (HTTP) socket timeouts, and each events (SSE) poll holds the worker for about 0.6 s. | Avoid other web actions during uploads; close idle tabs. | Open. |
| Power (FeatherS3) | In Performance, Balanced or UltraSaver mode the idle downclock changes the CPU clock, which once collided with in-flight sensor reads such as GPS (fixed in v0.98.8: the switch now drains the I2C buses first). The ESP32-S3 switch path changed again on 2026-11-08 (MSPI speed-mode sync) and is host-tested only; a 30-minute bench soak with GPS running is pending. | Adaptive (the default) or Locked, which do not change the clock at idle. | Open. |
| ESP-NOW security | Session keys, the rekey private key, the bond token and the decrypt buffer live in PSRAM, so with flash encryption off they can be read with bench (physical) access to the device. | Enable flash encryption (for example `feathers3_fe`); re-bond the other devices after one is lost. | Open. |
| Time | Plain SNTP replies are trusted as they arrive (lwIP steps the clock before the firmware sees them), so an attacker on the same LAN can set the device clock, moving timed automations and timestamps. | Use a trusted network. | Open. |
| Device handover | `factoryreset` removes the accounts, their settings and transcripts, and the phone-pipe code; saved WiFi networks, MQTT and LLM endpoint credentials, other Bluetooth bonds and the ESP-NOW identity and keys stay. | Before giving a device away, erase the whole flash over the cable (`tools/build_board.sh <board> -p PORT erase-flash`) and flash it again; see the User Guide, Account recovery. | Open. |
