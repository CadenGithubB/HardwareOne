## 1. Corrected findings

Claims where the truth differs from the original audit doc (or from the session's stated facts).

1. **"Near-zero cost DST" — CORRECTED, verdict is GO but the cost claim was wrong.** The libc half *is* genuinely free: this build's newlib parses full POSIX M-rules, quoted designators, and hh:mm offsets (verified by sscanf format strings in the shipped `libc.a(libc_a-tzset_r.o)`), and `tzset`/`__tzcalc_limits`/`mktime`/`localtime_r` are already linked in `build/hardwareone-idf.elf` (nm: all `T`) — **zero marginal flash**. But "a rule table + one gSettings field, no other code change" is wrong on three counts: (a) Arduino `configTime()` unconditionally rewrites TZ with a rule-less string (`esp32-hal-time.c:24-45`, called at `:77`) on **every** `setupNTP()` (4 call paths), so an unaccompanied rule is silently stripped on every WiFi boot — worse than not shipping; (b) the G2 glasses receive a static quarter-hour scalar (`G2_Glasses.cpp:8412`, `:8462`) with no rule engine and no self-heal — 1 h wrong for the entire DST season; (c) ~9 further static-offset consumers. Real scope: ~280–330 lines across ~9 files (phase 1) + ~100 (phase 2), two glasses HW sessions, one automation bench session. **Ship as an all-or-nothing phase 1 or not at all** (see plan, Stage 3).

2. **Fall-back ambiguous local time resolves to the SECOND occurrence (standard), not the first.** Audit line ~835 "(ii) a fall-back ambiguous hour resolves to the first occurrence" is refuted by the toolchain's actual mktime (espressif/newlib-esp32@9a0d3915, the commit id embedded in `libc_a-tzset.o`): the ambiguous window leaves `isdst = -1` and the final offset application picks std. Spring-forward nonexistent 02:30 maps to wall 03:30. Both single-fire, monotonic. Do not "fix" any code back toward line 835; T-DST-3 settles it empirically on-device.

3. **`Clock::applyTimezone()` sign bug: the broken case is EAST-of-UTC sub-hour offsets.** Audit POLISH #2 is correct; an intermediate fix draft inverted it. `tzOffsetMinutes = +30` → `offset/3600` truncates to 0 → `"UTC0:30:00"` = 30 min *west* (1 h error); `-30` renders correctly today. Fix: sign from `offset < 0`, format `labs(offset)/3600`.

4. **`configTime` does NOT run its sntp calls under the tcpip core lock in this tree.** The session-prelude "verified fact" holds only when `CONFIG_LWIP_TCPIP_CORE_LOCKING` is enabled — it is **not set** (sdkconfig:2127), so the lock blocks at `esp32-hal-time.c:55-59/:71-75` compile out. Arduino's path is raw and unlocked (tolerated wart; strengthens the optional native-`esp_sntp_*` variant, which marshals via `tcpip_callback`).

5. **No back-to-back double `sntp_init` at boot** (audit :213 wrong): `HardwareOne.cpp:1787-1800` is a mutually exclusive if/else. And **audit MUST FIX #19's "drop the redundant setupNTP() at HardwareOne.cpp:1793" is refuted** by its own verifier note: :1793 is the *only* `sntp_init` on the RTC-provided-time path. Keep it.

6. **`sntp_stop`/`sntp_init` cycles do not leak.** Core `sntp_stop` frees everything `sntp_init` allocates (lwip sntp.c:714-726, :686-701). The real (bounded) misbehavior: each cycle discards in-flight/retry state and re-arms a fresh random 0–5 s startup delay (port lwipopts.h:1580-1585, `CONFIG_LWIP_SNTP_MAXIMUM_STARTUP_DELAY=5000` — the in-code comment at `System_Utils.cpp:2386-2390` claiming 100 ms is false until the config change lands).

7. **The audit's ring duty-matrix row is stale, and the in-tree fix exposed a NEW defect.** Ring adoption *does* write a boot anchor now (uncommitted, `G2_Ring.cpp:468`). But `writeBootAnchor()` appends unconditionally (`System_User.cpp:3345-3352`) and `findMatchingAnchor()` returns the FIRST match (`:3014-3021`), so ring-adopt followed by a later real NTP sync writes two anchors with the same `gNTPAnchorId` and the **stale ring anchor wins user-timestamp resolution forever**. `writeBootAnchor` must become an upsert.

8. **`rtcSyncToSystem` has 3 callers, not 2**: rtcTask (`i2csensor_ds3231.cpp:463`), NTP-timeout fallback (`System_Utils.cpp:2483`), **and `cmd_rtcsync`** (`:780-786`) — the user-invocable path that re-fires the TZ-clobber bug with zero post-step duties. It also has no year-plausibility guard (dead-battery DS3231 can step a good clock to 2000).

9. **REFUTED: "rtcEarlyBootSync runs before filesystem/debug, so duties must be skipped."** Its call site (`HardwareOne.cpp:1584`) is preceded by `initFilesystem` (:1337, boot-seq/anchor id already bumped), `initDebugSystem` (:1523), and `applySettings` (:1524, TZ live). No duty is structurally unsafe there; heavy FS duties are merely better *deferred* to the first loop lap, which the plan does uniformly.

10. **REFUTED: `tm_gmtoff` shortcut.** Toolchain `time.h:48-49` guards it on `__TM_GMTOFF`, which nothing defines. The localtime_r/gmtime_r delta method is required.

11. **REFUTED: wizard timezone table duplicated in SetupWizardMode.** One canonical table (`System_SetupWizard.cpp:94-125`, **25 entries, not the audit's 27**), shared via `getTimezones()`. 15. **New defects the audit lacks**, found during verification: (a) **weekInterval biweekly parity flips across a DST transition** (`System_Automation.cpp:2365-2369` floors `(cand-anchor)/604800`); the verifier-mandated civil-day differencing (audit :66) subsumes both this and the filed late-anchor bug — do not ship rounding instead.
