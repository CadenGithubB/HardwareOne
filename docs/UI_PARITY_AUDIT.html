The structural difference still holds

The OLED reaches every feature through its CLI Input mode — an on-screen keyboard that runs any serial command under a local-display identity. So OLED "gaps" are about discoverable graphical screens, not raw reachability. The G2 has no free-form command entry, so its gaps are genuine reachability gaps — no page means the wearer cannot get there at all. This pass closed the highest-value G2 reachability gaps first. The Android app sits with the OLED: its Console screen runs any CLI verb over BLE, so reachability is near-total and its gaps are discoverability gaps — with one twist unique to the app: several screens that do exist can't actually write. That defect is the next callout, and it is why the app's headline is 38/55 rather than the nominal 41.

Audited entry-by-entry — the app's core defect is write integrity, not missing screens

All 407 settings entries across 34 firmware modules were traced from app editor to firmware store, each verdict adversarially re-verified: 276 writes (68%) are broken; only 123 (30%) work — outside the sensor cards the settings UI is largely display-only while looking writable. 243 entries send a jsonKey that is no registered verb (Unknown command: all 37 espnow rows, all 16 LLM knobs, all 6 bluetooth, all 6 power, edgeimpulse, notifications, batteryLog, most of debug); 23 bools reach a parser that accepts only 1|true, so the app's on silently writes false while the device replies "Configuration updated"; selects send raw option tokens that get rejected or stored verbatim. Worst: six debug rows misfire into other features' commands via the dispatcher's prefix match — the camera flag named capture runs the shutter with no admin, writing a real photo whenever the camera is open; broadcast spams all consoles. And failures are invisible: errors land only in the Console log, toggles never move, sliders keep showing the unapplied value. The fix: emit cmd in buildModuleControlsJson (System_Settings.cpp:2652 — the web settings-schema serializer already emits cmdKey at :2767), prefer it in setControl, normalize tokens (bool → lowercase 1/0, selects → value-part, floats → Locale.ROOT), and surface errors. Full report: docs/CONTROLS_WRITE_INTEGRITY.md + per-entry controls-write-audit.csv.

Groundwork that shipped alongside the screens

  • Non-blocking LED effect engine — ledEffectStart / Tick replaced the blocking loop, so effects no longer stall cmd_exec for their whole duration (the old duration-arg footgun).
  • Shared LED core — one color / effect / brightness table feeds both the G2 and OLED pages; neither surface duplicates the list.
  • System_TextPager extracted into system utilities — the pager that was G2-only now backs G2 Files/Settings/ESPNow and the new OLED file viewer.
  • Serial fileview <path> [page] — 8 KB hard cut replaced with a 60 KB windowed, line-batched read; surfaced and fixed a latent 255-byte broadcastOutput clamp.
  • 4× task-stack accounting fix — stacks are counted in bytes, not words; the LOW / CRITICAL headroom warnings had been 4× too lax across every task.
  • G2 status polish — PSRAM now shows in KB below 1 MB (was "0 MB"); the fuel-gauge battery row is hidden on boards without one (XIAO / QT Py, was "---"); the LED page's "Unknown" header wiring gap is fixed; "ESP-NOW App" relabeled "ESP-NOW".
  • wifirm persist bug fixed — removing the last saved network never reached disk (the settings serializer skipped the array rewrite when the list emptied, and the merge-read resurrected the old entry on reboot). The rewrite now always runs, guarded by a settings-loaded-OK flag, and wifi commands report a failed persist instead of "OK".
  • Reboot crash fixed — the arduino_events task stack had been cut to 2.5 KB by the words-vs-bytes footgun inside the gitignored vendored Arduino tree (the one place the July stack pass couldn't see). Restored to 4 KB via a tracked CMake define, and the WiFi disconnect logger now defers its heavy work to the main loop.
  • Dead legacy wifi fields removed — the frozen-empty network.wifi.ssid/password keys are gone from settings, and offline wifistatus now shows the real top-priority saved SSID instead of a blank.

Already shipped before this pass — don't rebuild these

G2 LLM reader already exists — a streaming on-lens viewer with chat history and one-tap "Re-run last", reachable from the Apps launcher. Genuinely missing is only model load/swap and typing a new prompt from the lens.

G2 settings are not read-only — task-specific editors exist (BOOL toggles, enum pick, numeric step, string via the char-picker keyboard). Only the generic full-registry browser treats a row tap as a no-op.

OLED clock/NTP, debug flags, and ANO remap are all present via dedicated modes or the generic Settings editor — not CLI-only.

Clock / NTP — wall clock on Status S specced

Verified feasible — ~1 line. Fold a live HH:MM in front of the existing uptime line in buildG2StatusSnapshot via Clock::formatHHMMLocal(Clock::epochSeconds()) (live read, already local tz; falls back to --:-- before sync). No new body line, no geometry change — the Status diff-gate repaints one line per minute on the 5s tick. Confirmed the read-only display is fully separate from the outbound G2 TIME_SYNC path (the quarter-hours encoding), so it can't touch the glasses' native RTC.

Notifications center M deferred

Deferred to the better route: the G2's own native firmware. The glasses' vendor firmware has a native notification system; tapping into that — so notifications render through the glasses' own notification UI rather than a custom ESP32-side lens page — would be a tremendous benefit and is the intended path. It still needs to be reverse-engineered (a later effort). On the ESP32 side, the v0.98.7 pipeline (48-event ring, queue-enabled kinds) has no lens surface today — g2ShowNotification is a placeholder that wipes the lens — so a custom list+text page is the fallback only if the native route doesn't pan out.

Write integrity — settings cards that can't save S defect

The cross-cutting fix detailed in the callout above, now measured: 276 of 407 settings writes broken (68%) — 243 dead-verb, 23 silent-false bools, 6 debug-card misfires (one toggle fires the shutter). All six misfires are resolved by the same routing fix, not per-row gates: emit cmd in the controls-json contract, prefer it in setControl, normalize tokens, surface errors. System control — dashboard with no power buttons S partial

Status mirrors the whole status json dashboard, but reboot, ramflush, broadcast and factory reset have no buttons — Console-typing only. All four are verified text verbs; one Power card with a reconnect countdown covers it. factoryreset is superadmin and needs the typed-yes confirm step.

ESP-NOW — pairing is built but not wired M partial

The app's richest feature (chat, remote exec, remote FS, fetch) is missing its front door: pairEspNow() sits in the ViewModel with zero call sites — the Discovered list is read-only, so onboarding a peer still means the Console or web. Also absent: a broadcast composer, file send (espnowsendfile; fetch works), and the mesh-passphrase setter (superadmin). The unpair flow's reload-after-write pattern is the template.

WiFi — can't get the device onto a new network M partial

Status shows the live connection and settings cover reconnect/NTP/timezone, but saved-network CRUD (wifiadd/wifirm/wifipromote), scan-and-connect (wifiscan json/openwifi) and disconnect have no screen. Footguns: the scan blocks for seconds, closewifi also stops the web server, and wifiadd carries the password over BLE — that's Secure Channel's job.

G2 glasses — one status boolean, no screen M missing

The app knows exactly one G2 fact (connected: yes/no) while g2Commands[] is huge and mostly non-admin fire-and-forget: g2show / g2ai / g2notify push, lens-page one-shots, g2nav, g2battery. Limits: openg2/closeg2 are admin, g2status replies text not JSON, and G2 mic WAVs land on SD — the Mic screen's pull loop already handles those.

Automations — control shipped, authoring missing M partial

List / Run / Arm / Enable / Delete work today; creating a rule still means hand-typing automation add name=… type=event on=…. The firmware is form-ready (clean key=value args; events kinds json feeds a trigger picker). No edit verb — edit is delete + re-add; all mutations admin-gated. The OLED just shipped this wizard; the phone keyboard makes it strictly easier here.

Users & sessions — no admin surface, not even Logout M partial

Login is polished (biometric-stored credentials, auto-login) but there's no user list, promote/ban, password change, or session revoke — and no Logout button; bare logout targets the SERIAL session, so the button must send logout bluetooth. userlist / sessionlist / pendinglist json are capture-friendly; every action verb is a one-line text reply. Fold in registration: a request-account link (userrequest, non-admin) + a pending-approvals card.

Peer sensors — the mesh payoff is invisible M partial

espnowsensorstatus json — the master's remote-sensor cache — is consumed nowhere; the Sensors page reads local sensors only. One viewer card closes the sensors-hub and bonded-peer gaps at once, reusing the recursive reading renderer. Arming a peer's stream needs admin bondstream or remote exec, and the single capture slot forces polite interleaving with the 1 s poll.

MQTT — config yes, runtime no S partial

The settings card edits every broker/topic field (except the isSecret password, by policy), but "why won't Home Assistant connect" still needs the Console: no openmqtt/closemqtt buttons, and the mqttstatus json lastError field — the one thing a debugging user needs — is never shown.

OLED remote + animation picker S partial

The oled settings card edits the persisted half; the live half — oledmode's 17 modes, oledtext push, oledclear, oledstatus json — has no surface. The 12 animations are Console-only too (oledanim; names hardcoded, no enumeration verb; chain oledstart when the display task is stopped).

Speech / ESP-SR — three knobs, no voice surface M partial

You can't see whether voice is armed or start the pipeline. srstatus is pure JSON (same pattern as llmstatus) → a live card with wake/command counts; srstart / srstop / voicearm / voicedisarm are non-admin text buttons. The MultiNet vocabulary editor (srcmdslist/add/del, admin, scraped) is the real work. No BLE push — wake detections appear as counter deltas between polls.

Video recording — firmware-complete, app-absent M missing

camerarecord start|stop, cameravideolist json and cameravideodelete manage MJPEG-AVIs on SD; the app references none of them. Record / list / delete drop straight onto CameraScreen's seams. In-app playback does not: Android ships no MJPEG-AVI codec, and multi-MB pulls over the 2 KB fileread window take minutes — explicitly out of the first cut.

Battery — live gauge full, history dark M partial

Voltage / % / rate / ETA show everywhere (Status, connect card, home-screen widget) but /battery.csv is never pulled or plotted. The chart is all existing seams: batterylog on + the secure windowed pull + a Canvas plot. The batteryLog settings card is a dead-row trap (no cmdKeys, ms-vs-seconds mismatch) — part of the write-integrity fix.

Files — view-only viewer, no microSD M partial

The manager is real (permission-aware browse, secure up/down, create/rename/delete) but the text viewer can't edit, JPEGs only render in the Camera gallery's fixed folders, and sdinfo / sdmount / sdformat have no surface anywhere (sdinfo json is capture-ready; sdformat superadmin + confirm).

Thermal — the only surface without the heat-map M fw-blocked

Open/close, live min/avg/max and full tuning ship — but no CLI verb emits the 768-px frame (thermalBuildDataJSON is web/MQTT-only and oversized for the ~2 KB BLE reply cap), so the phone alone shows numbers where every other surface shows the picture. Needs a quantized thermalframe json firmware verb; a Compose canvas then renders ~1 fps.

Small action-rows & wired fixes S partial

One-verb adds on existing cards: RTC — the sync labels are inverted (the "Sync → RTC" button sends rtcsync to, which firmware defines as RTC→system — swap them; add rtcset); NTP — ntpsync button + time json provenance (ntp / rtc / phone); Mic — gain / sample-rate / bit-depth rows; I2C — a diagnostics accordion (i2chealth / i2cmetrics json); sensor-log — start/stop/status plus the broken bitmask select; images — send-to-peer (imagesend); Edge Impulse — an Analyze button (eifile / eidetect reply JSON only on detections — scrape, don't capture).
